# 真实数据接入指南（用户向）

本文档教你如何把「Insta360 达人营销数据洞察平台」从演示 Mock 数据切换到**抖音 / B站 / 小红书的真实数据**。

---

## 0. 一句话结论

代码已经**就绪可运行**。现在不填任何凭证，看板显示的是演示数据（Mock）。
等到你拿到任意平台的 `appkey` / `access_token`，**只改环境变量、重启后端**，看板就会切到真实数据——
不用改任何业务代码。没填凭证时看板也不会崩，会自动回退演示数据。

---

## 1. 快速开始（默认就是演示数据）

```bash
cd backend
cp .env.example .env      # 不填任何值
# SOURCE 留空或 = mock
go run .                  # 看板照常显示演示数据
```

---

## 2. 接入抖音（最易：应用级 token，无需用户授权）

1. 去 [抖音开放平台](https://open.douyin.com) 创建**网站应用**并通过审核，拿到 `client_key` / `client_secret`。
2. 在 `.env` 填：
   ```ini
   SOURCE=douyin
   DOUYIN_CLIENT_KEY=你的client_key
   DOUYIN_CLIENT_SECRET=你的client_secret
   ```
3. 重启后端。后端会自动走 `client_token` 流程拉取数据。
   - 也可以不走应用级，而是用已授权的用户 `access_token`：`DOUYIN_ACCESS_TOKEN=xxx`（优先级更高）。

> 注意：抖音**达人营销汇总数据**（粉丝/播放/互动/榜单）在**巨量星图**（企业资质）。
> 公开接口只能取授权账号自身的资料。本期已按星图文档结构写好映射，企业 appkey + scope 到位即可真实返回；
> 公开接口拿不到的维度会回退演示数据（看板是「真实 + 演示」混合，不会空）。

---

## 3. 接入 B站（需要用户授权 token）

B站**没有应用级 token**，必须先用授权码流程拿到用户 `access_token` 再填进来。

1. 去 [哔哩哔哩开放平台](https://openhome.bilibili.com) 入驻并创建应用，拿到 `client_id` / `client_secret`。
2. 走 OAuth2 授权码流程（见下「授权流程简图」）拿到 `access_token`，填：
   ```ini
   SOURCE=bilibili
   BILIBILI_ACCESS_TOKEN=你拿到的access_token
   BILIBILI_CLIENT_ID=你的client_id
   BILIBILI_CLIENT_SECRET=你的client_secret
   ```
3. 重启后端。所有创作者数据接口会自动带 **HMAC-SHA256 v2 签名**。

---

## 4. 接入小红书（蒲公英门槛高；可用聚合）

- **蒲公英官方**：门槛极高（品牌年消耗 500W+ 或白名单）。有资质的话走商家授权拿 `access_token` 填 `XHS_ACCESS_TOKEN`。
- **第三方聚合**（如 Just One API）：门槛低，把 API key 填 `XHS_ACCESS_TOKEN`，并把 `XHS_BASE_URL`
  指向聚合网关（如 `https://api.justoneapi.com`），`XHS_USER_ID` 填目标达人 id：
  ```ini
  SOURCE=xiaohongshu
  XHS_ACCESS_TOKEN=你的聚合API key
  XHS_USER_ID=目标达人userId
  XHS_BASE_URL=https://api.justoneapi.com
  ```

---

## 5. OAuth2 授权码流程简图（B站 / 小红书需要）

```
1. 拼接授权 URL(带 client_id / app_id / redirect_uri / state)
2. 用户浏览器打开 → 登录并同意授权
3. 平台重定向到 redirect_uri?code=xxx
4. 你的服务端用 code + secret 换 access_token(有过期时间,需刷新)
5. 把 access_token 填进 .env 的 *_ACCESS_TOKEN
```

> 本期后端**未内置授权回调页**（那是单独的登录功能）。拿到 token 后手动填 env 即可先跑通数据。
> 后续会补「授权回调 → 落库 token → 注入 adapter」的无人值守拉数链路。

---

## 6. 回退机制（重要）

后端对每个数据方法都做了**双源兜底**：

- 真实源返回 `ErrNotImplemented`（未接入 / 无凭证）→ 用 Mock。
- 真实源调用报错（网络/限流/字段缺失）→ 也用 Mock。

所以：
- `SOURCE=douyin` 但没填凭证 → 看板仍是演示数据，**不报错、不空白**。
- 填了凭证但某维度平台无权限 → 该维度回退演示，其他维度用真实，**看板永远有内容**。

---

## 7. 切换检查清单

- [ ] `.env` 里 `SOURCE` 设为目标平台
- [ ] 对应平台的 `ACCESS_TOKEN` 或 `CLIENT_KEY/SECRET` 已填
- [ ] 小红书额外填了 `XHS_USER_ID` / `XHS_BASE_URL`（用聚合时）
- [ ] 重启后端（`go run .` 或重新编译）
- [ ] 打开看板，确认数据已变化（不再是固定演示值）
- [ ] 字段若对不上：用平台返回 JSON 核对 adapter 内的「平台响应结构」字段名，按最新文档微调

---

## 8. 已知限制（诚实告知）

1. 抖音 / B站 / 小红书 的**达人营销汇总数据**需企业资质，公开接口只能取授权账号自身数据。
2. 小红书蒲公英官方门槛极高，普通开发者建议先用聚合网关验证链路。
3. 达人 / 内容 / 市场 / 品牌 四域本期未做真实映射（回退演示），待凭证到位后逐域补全。
4. 平台响应字段名基于公开/文档结构的合理实现，拿到真实 appkey 后首要核对项是**字段名与单位**。
