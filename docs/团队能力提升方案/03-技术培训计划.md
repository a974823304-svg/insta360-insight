# 技术培训计划

> 适用团队：Insta360 达人营销数据洞察平台研发组
> 周期：6 个月（2 季度）
> 设计思路：从工程化基础 → 语言进阶 → AI 应用工程 → 数据/可观测性。每模块绑定本项目实战，避免"学完用不上"。

---

## 0. 培训目标

| 维度 | 当前（基线） | 目标（6 月后） |
|---|---|---|
| 测试覆盖率 | 0% | Go 60%+ / Python 60%+ / 前端 50%+ |
| CI/CD | 无 | lint + test + build 全自动化 |
| 工程化思维 | 项目能跑但靠人盯 | 自动化门禁 + 标准化流程 |
| LLM 应用能力 | 能调 SDK | 能设计 prompt + 兜底链 + 评测 |
| 可观测性 | 无 | 结构化日志 + 基础 metrics + trace 串联 |

## 2. 课程模块

### M1 · 工程化基础（必修 / 全员 / 第 1-2 周）

**目标**：让团队每个人都有"工程化思维"——写的代码能被别人 review、能被 CI 自动验证、能被后人维护。

**内容**：

| 主题 | 时长 | 形式 | 考核 |
|---|---|---|---|
| Git 进阶（rebase / cherry-pick / bisect） | 2h | 讲解 + 沙盒演练 | 完成 1 次冲突解决 + 1 次二分定位 bug |
| CI/CD 入门（GitHub Actions 实战） | 3h | 讲解 + 现场写 pipeline | 把现有项目加 CI，跑通 |
| Docker 入门（多阶段构建 / compose） | 3h | 讲解 + 上手 | 本项目三服务 compose 化（见 P1-9） |
| 测试入门（单测 / 集成 / E2E 区别） | 2h | 讲解 + 例子 | 给 `feature_extractor.py` 写第一组 pytest |
| Pre-commit + lint 配置 | 1h | 现场装 + 配 | 故意提交违反 lint 的 commit，看 hook 拦下 |

**实战绑定**（4 周持续）：
- 在本项目跑通 CI（lint + test）
- 在本项目落地 Dockerfile + compose
- 给 `internal/service/insight_service.go` + `ai/core/feature_extractor.py` 补首轮单测

**资源**：
- 官方：https://docs.github.com/en/actions
- 书：《持续交付》Jez Humble
- 视频：TechWorld with Nana "Docker for Beginners"

### M2 · Go 后端进阶（必修 / 后端 / 第 3-4 周）

**目标**：写出**生产级** Go 代码——不是能跑就行，而是可观测、可恢复、可调优。

**内容**：

| 主题 | 时长 | 形式 | 考核 |
|---|---|---|---|
| `context` 传播与超时控制 | 2h | 讲解 + 重构现有 handler | 每个外部调用都带 ctx + 超时 |
| 错误处理：sentinel / wrapping / `errors.Is/As` | 2h | 讲解 + 代码 review | 重构 ai_service.go 的错误链路 |
| 并发：goroutine / channel / errgroup | 3h | 讲解 + 实战 | 给 insight_service 加并发预聚合（mock 并行拉 9 个数据源） |
| 性能：pprof / trace / benchmark | 3h | 现场跑 pprof | 用 benchmark 优化 mock 数据生成 |
| Gin 进阶：中间件 / 路由分组 / validator | 2h | 讲解 + 重构 | 加 RequestID、AccessLog、结构化日志中间件 |
| 测试：table-driven / testify / httptest | 3h | 讲解 + 实战 | 给 9 个 handler 写 httptest |

**实战绑定**（本项目）：
- 给 `middleware.go` 加 RequestID + slog（替代手写 itoa）
- 给 `service/insight_service.go` 加单测（目标覆盖率 60%）
- 给 `api/handler/insight.go` 加 httptest 端到端测试
- 接入 `golangci-lint`（[02 § 11.1](./02-团队代码规范与最佳实践指南.md#11-工具链配置)）

**资源**：
- 官方：https://go.dev/blog/
- 书：《Go 语言高级编程》柴大
- 书：《Concurrency in Go》Katherine Cox-Buday

### M3 · Python AI 应用工程（必修 / AI 工程师 / 第 3-5 周）

**目标**：把"能跑 prompt"升级到"能交付 LLM 应用"——可评测、可降级、可审计。

**内容**：

| 主题 | 时长 | 形式 | 考核 |
|---|---|---|---|
| Pydantic v2 高级用法（discriminated union / 自定义 validator） | 2h | 讲解 + 重构 schemas.py | 用 validator 校验 InsightRequest |
| 异步：`asyncio` / 异步 SDK / `Semaphore` 限流 | 2h | 讲解 + 重构 llm_client | LLM 调用并发限制 + 超时 |
| 测试：pytest / fixture / parametrize / mock | 3h | 讲解 + 实战 | 给 feature_extractor / prompt_builder 各写 10+ 用例 |
| Prompt Engineering 进阶（结构化 / CoT / 工具调用） | 4h | 讲解 + workshop | 重写 system prompt，让 LLM 输出更稳 |
| 兜底链设计（rule-based / retrieval / human-in-loop） | 2h | 讲解 + 实战 | 给 insight_engine 加二级兜底 |
| 可观测性（Langfuse / Phoenix trace） | 3h | 现场装 + 接入 | 把每次 LLM 调用的 prompt + response + score 入库 |
| LLM 评测（golden set / LLM-as-judge） | 3h | 讲解 + 建评测集 | 建 50 条 insight golden set，跑自动化评测 |

**实战绑定**（本项目）：
- 重写 `prompt_builder.py` 的 `parse_response`（修 P0-2 容错）
- 给 `feature_extractor.py` + `prompt_builder.py` 写 pytest（目标覆盖率 80%）
- 接入 `tenacity` 重试 + `pybreaker` 熔断（修 P1-6）
- 把 insight 的 prompt + response 接入 Langfuse，落到 `/tmp/langfuse.db` 本地查看

**资源**：
- 官方：https://docs.pydantic.dev/latest/
- 书：《Designing Machine Learning Systems》Chip Huyen（重点看第 7/8 章）
- 视频：Andrej Karpathy "Intro to Large Language Models"
- 工具：Langfuse / Phoenix / PromptFoo

## 7. 常见问题

**Q：新人入职怎么快速上手？**
A：入职第 1 周跑完 `make dev` + 把 [02 § 11 工具链配置](./02-团队代码规范与最佳实践指南.md#11-工具链配置) 装好；第 2-4 周挑 2 个 "good first issue" 走完完整 MR 流程。

**Q：线上事故来了怎么办？**
A：先止血（关流量 / 回滚），再排障（日志 / trace / metrics），**48h 内**写 Postmortem 归档到 `docs/postmortem/`，全员 review。

**Q：技术债太多没时间修怎么办？**
A：每个迭代预留 **20% 时间**给技术债；优先级参考 [01 § 0 总体结论](./01-代码质量审查报告.md#0-总体结论)，按 P0→P1→P2 推进。

**Q：怎么衡量培训有没有用？**
A：看 3 个数据：
1. 测试覆盖率（P0-3 目标）
2. CI 红灯次数 / 修复时长
3. 线上 P0/P1 bug 数

持续 3 个月数据向好 → 培训有效；停滞 → 调整课程。
