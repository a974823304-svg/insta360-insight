## 1. 总体原则

| # | 原则 | 一句话解释 |
|---|---|---|
| 1 | **KISS** | "Keep It Simple, Stupid"——能用 5 行写清楚的，别写 50 行 |
| 2 | **YAGNI** | "You Aren't Gonna Need It"——不写"将来可能用到"的抽象 |
| 3 | **单一职责** | 一个模块只做一件事；一个函数只做一件事 |
| 4 | **明确优于隐式** | 类型/参数/返回值要明确，不依赖运行时"心有灵犀" |
| 5 | **错误显式** | 错误要可见、要可定位，不要 `try-catch` 后静默吞掉 |
| 6 | **向后兼容** | 改 API 时兼容旧调用方；删字段前先 deprecate 一个版本 |
| 7 | **自动化优于人肉** | 能用脚本/lint/CI 拦的，不靠 reviewer 眼睛盯 |
| 8 | **代码即文档** | 命名 + 注释 + 测试 三件套到位，胜过单独维护一份"设计文档"（但 ADR 例外） |

### 2.2 规则

- **`internal/` 严禁跨层引用**：handler 不能 import mock；service 不能 import api/router。单向：`router → handler → service → store/mock`。
- **`core/` 无框架依赖**：AI 引擎的 `core/` 模块**不 import fastapi**，只 import 标准库 + `core` 内部，方便 100% 单测覆盖。
- **测试目录就近**：Go 测试文件 `xxx_test.go` 与被测文件**同包同目录**；Python `tests/` 与 `ai/` 平级。
- **新功能先放对位置**：找不到对应目录时，**先讨论目录结构再写代码**，避免散落在根目录。

## 3. 命名规范

### 3.1 通用

| 类别 | 规则 | 反例 |
|---|---|---|
| 文件名 | 全小写，下划线分词（Python/Go） / 短横线（前端组件多单词） | `UserService.go` ❌ |
| 类/接口/组件 | 大驼峰 | `InsightService`、`KpiCard.vue` ✅ |
| 函数/方法 | 小驼峰（Go/TS/Vue） / 小写下划线（Python） | `getInsight` ✅, `get_insight` ✅ |
| 变量 | 小驼峰（Go/TS） / 小写下划线（Python） | 同上 |
| 常量 | 全大写下划线 | `MAX_RETRY = 3` |
| 布尔变量 | `is_xxx` / `xxx_up` / `has_xxx` 前缀 | `isLoading` ✅, `loading` ❌ |
| 私有成员 | 前缀 `_` 或显式 `private` | `_internal_state` |

### 3.2 Go

- 包名：小写单词，**不要**用下划线或驼峰（`package insight` not `package insight_service`）。
- 接口命名：以行为命名，单方法接口用 `-er` 后缀（`Reader`, `Writer`, `InsightGenerator`）。
- 错误变量：`ErrNotFound`、`ErrInvalidFilter`，前缀 `Err`。
- 接收者（receiver）：**1-2 字母**类型首字母，全文件统一（不要同一类型有时 `s *Service` 有时 `svc *Service`）。

### 3.3 Python

- 模块/包：全小写，不带下划线（PEP 8 允许但项目里统一不用）。
- 类：大驼峰。
- 函数/变量：小写下划线。
- 私有：前缀 `_`（不强制，但约定）。
- 类型注解：函数签名必须有；可以用 `from __future__ import annotations` 避免运行时求值。
- 不要用 `type: ignore` 逃逸；如果非用，加 comment 说明原因。

### 3.4 Vue / TypeScript

- 组件文件：大驼峰 `KpiCard.vue`（多单词）、单单词 `App.vue`。
- composable：`useXxx.ts`（如 `useEcharts.ts`）。
- store：`useXxxStore`（Pinia 规范）。
- props：`camelCase` 声明、模板里用 `kebab-case`（Vue 3 都支持，但团队统一 kebab）。
- emit：`kebab-case`（`update:value`、`filter-change`）。
- 业务常量：从 `constants/` 取，不要在组件里硬编码字符串。

## 4. 代码结构

### 4.1 函数粒度

- **一个函数 ≤ 50 行**（不含注释/空行）。超过 → 拆。
- **参数 ≤ 5 个**。超过 → 引入结构体（Go）/ dataclass（Python）/ options object（TS）。
- **嵌套 ≤ 3 层**。超过 → 早返回（guard clauses）。

### 4.2 模块依赖

- 单向依赖：`router → handler → service → store`，**禁止反向依赖**。
- 跨层调用通过接口（Go）或 Protocol（Python `typing.Protocol`），便于 mock 测试。

### 4.3 Vue 组件

- `<script setup lang="ts">` 优先（如果开了 TS）。
- **Props 显式声明 `type` + `required`**，避免 `any`。
- **Emits 显式声明**，不要 `$emit('xxx')` 一把梭。
- 模板里**不写复杂表达式**：超过 1 个三元或 2 个方法调用 → 抽 computed。
- 业务逻辑放 store 或 composable，组件**只做渲染 + 事件转发**。

## 5. 接口契约

### 5.1 统一响应

**约定不变**（已写在 `backend/internal/model/types.go:118`）：
```json
{
  "code": 0,            // 0 = 成功；非 0 = 业务错误码
  "message": "可选的错误描述",
  "data": <任意业务负载>
}
```

**业务错误码分段**（团队约定）：
- `0`：成功
- `1xxx`：参数错误（1001=字段缺失，1002=格式错，1003=超长度）
- `2xxx`：业务错误（2001=数据不存在，2002=权限不足）
- `3xxx`：上游错误（3001=LLM 调用失败，3002=数据库超时）
- `5xxx`：服务器内部错误

### 5.2 字段一致

- **同一字段名，三端一致**：`backend/internal/model/types.go`（Go struct tag） ↔ `ai/models/schemas.py`（Pydantic） ↔ `frontend/src/api/fallback-data.js`（mock）。
- 字段命名用 `snake_case`（JSON）/ `PascalCase`（Go struct）/ `snake_case`（Python）。
- 增减字段要走 `scripts/check_contract.py`（见 [01 § P1-7](./01-代码质量审查报告.md#p1-7-前端-store-与后端-mock-字段漂移风险)），CI 必跑。

### 5.3 数组响应

- 顶层直接返回数组（Go `c.JSON(200, arr)`）→ 不符合本项目约定。**必须包 `model.OK(arr)`**，前端 store 才能稳定解构。

## 6. 错误处理

### 6.1 Go

- **永远不要 `panic` 做业务控制流**；`panic` 只用于"不可能发生"的状态。
- 错误传递：`fmt.Errorf("xxx failed: %w", err)`，**保留链**。
- 错误日志：handler 层负责记日志 + 转 HTTP code；service 层只返回错误，**不记日志**。
- 自定义错误：`var ErrNotFound = errors.New("not found")`，sentinel 错误用 `errors.Is` 判断。

```go
// service
func (s *InsightService) GetKpi(f model.Filter) ([]model.KpiCard, error) {
    if err := f.Validate(); err != nil {
        return nil, fmt.Errorf("invalid filter: %w", err)
    }
    rows, err := s.store.Query(f)
    if err != nil {
        return nil, fmt.Errorf("store query: %w", err)
    }
    return rows, nil
}

// handler
func (h *Insight) Kpi(c *gin.Context) {
    f := bindFilter(c)
    rows, err := h.svc.GetKpi(f)
    if err != nil {
        slog.Error("kpi failed", "err", err, "filter", f)
        c.JSON(http.StatusInternalServerError, model.Fail(5000, err.Error()))
        return
    }
    c.JSON(http.StatusOK, model.OK(rows))
}
```

### 6.2 Python

- 自定义异常体系：`class InsightEngineError(Exception)`、`class LLMUnavailableError(InsightEngineError)`。
- 不用裸 `except:`，必须指定异常类型；`except Exception` 只在兜底层（AI engine 的兜底层）。
- LLM 失败 → 抛 `LLMUnavailableError`；外层 `except` 转规则方案 + **记结构化日志**（包含 raw 便于排障）。

### 6.3 Vue / 前端

- axios interceptor 统一处理错误，**不在每个组件里写 try-catch**。
- 错误暴露给 UI：用户可见错误用 ElMessage；技术错误入 console.error + 上报埋点。
- Store 的 `loadAll` 失败时**保留 fallback**，不抛给 UI（让 UI 不空白），同时把 `usedFallback.value = true`。

## 7. 日志规范

### 7.1 字段

每条日志至少包含：
- `timestamp`（ISO8601）
- `level`（debug/info/warn/error）
- `service`（组件名，如 `backend-http` / `ai-insight`）
- `request_id`（中间件注入）
- `message`（人类可读）
- 上下文（key-value，自由字段）

### 7.2 Level 约定

| Level | 何时用 |
|---|---|
| debug | 详细流程，仅 dev 开 |
| info | 关键节点（请求完成、任务开始） |
| warn | 可恢复异常（重试、兜底） |
| error | 不可恢复 / 需要人工介入 |

### 7.3 不要做的事

- 不要在循环里打 info 级日志（一条请求 100 条日志 = 灾难）。
- 不要把 PII（个人信息）/ API key / password 打出来。
- 不要用 `fmt.Println` / `console.log` 代替 logger。

## 8. 安全规范

| 项 | 要求 |
|---|---|
| CORS | **白名单 + Vary: Origin**，禁止反射 Origin |
| Auth | 所有非 `/api/health` 的接口走 JWT / OIDC；token 走 httpOnly cookie 或 Authorization 头 |
| 输入校验 | 入口（handler / FastAPI route）必须校验；白名单优于黑名单 |
| 密钥 | 不进 git；生产从 Vault / 云 KMS 读；本地 dev 用 `.env.local`（加入 `.gitignore`） |
| 依赖 | `go mod tidy` + `npm audit` + `pip-audit` 在 CI 必跑 |
| 序列化 | 不直接 `json.Marshal(user)` 暴露 password / token 字段（用 `json:"-"`） |
| LLM | 输出视为不可信：parse 失败兜底；展示给用户前过长度/敏感词检查 |

## 9. 性能规范

### 9.1 前端

- **ECharts 按需引入**（见 [01 § P1-4](./01-代码质量审查报告.md#p1-4-前端-echarts-全量引入性能)）。
- 单 chunk > 500KB 必须拆（vite `manualChunks`）。
- 列表渲染 > 100 条用虚拟滚动（`el-table-v2` / `@tanstack/vue-virtual`）。
- 图片：`loading="lazy"` + WebP 优先。
- 计算属性用 `computed` 而不是函数（缓存）。

### 9.2 后端

- 数仓查询：必须带超时（context.WithTimeout）；必须用 prepared statement / 参数化。
- 大结果集：流式返回（Gin `c.Stream` / SSE），不一次性 marshal。
- 缓存：可容忍分钟级延迟的查询走 Redis，cache key 含 filter 哈希。

### 9.3 AI

- LLM 调用并发限制：`asyncio.Semaphore(8)`。
- Prompt 长度控制：> 4K token 截断或分段。
- 规则兜底路径必须 **< 50ms**（LLM 路径可能 2-10s）。

### 10.1 覆盖目标（6 个月内）

| 层 | 目标覆盖率 |
|---|---|
| Go `internal/service` | 80% |
| Go `internal/api/handler` | 70% |
| Go `internal/model` | 90% |
| Python `ai/core/*` | 80% |
| Python `ai/api/*` | 60% |
| Vue `stores/*` | 70% |
| Vue `components/*` | 50% |

### 10.2 编写原则

- **测试金字塔**：70% 单元 + 20% 集成 + 10% E2E。
- **测试文件名**：`xxx_test.go` / `test_xxx.py` / `xxx.test.ts`。
- **测试函数命名**：Go `TestXxx_Method_Scenario`；Python `test_xxx_scenario`；TS `describe('Xxx').it('should ...')`。
- **AAA 模式**：Arrange / Act / Assert 清晰分段。
- **独立**：测试间不共享状态；用 fixture / factory function。
- **确定性**：不用 `time.Now()` 直接断言，用 `clock` 抽象或注入。

### 10.3 Go 示例

```go
func TestInsightService_Kpi_FilteredByRegion(t *testing.T) {
    // Arrange
    ds := NewDataset()
    svc := NewInsightService(ds)

    // Act
    got := svc.Kpi(model.Filter{Regions: []string{"亚太"}})

    // Assert
    if len(got) == 0 {
        t.Fatal("expected non-empty KPI")
    }
    for _, k := range got {
        if k.Key == "" {
            t.Errorf("KPI missing key: %+v", k)
        }
    }
}
```

## 12. Git 规范

### 12.1 分支模型

- `main`：受保护，永远可部署；只能通过 MR 合并。
- `feat/<scope>/<short-desc>`：新功能。
- `fix/<scope>/<short-desc>`：修 bug。
- `refactor/<scope>/<short-desc>`：重构（不改外部行为）。
- `chore/<scope>/<short-desc>`：工具链 / 文档。
- `release/vX.Y.Z`：发布分支（可选）。

### 12.2 Commit Message

用 [Conventional Commits](https://www.conventionalcommits.org/)：

```
feat(insight): add AI insight caching layer
fix(frontend): prevent v-for string explosion when API returns HTML
refactor(ai): extract feature extractor into standalone module
docs(readme): add local dev quickstart
chore(deps): bump echarts to 5.5.0
test(backend): add table-driven tests for InsightService
```

格式：`<type>(<scope>): <subject>`，subject ≤ 50 字，body 解释"为什么"。

### 12.3 MR / PR

- 单 MR ≤ 400 行 diff（不含自动生成）。
- 标题同 commit message，描述必须包含：
  1. **What**：改了什么
  2. **Why**：为什么改（关联 issue / 设计背景）
  3. **How to test**：测试步骤 / 截图 / 命令
  4. **Risk**：潜在影响
- 模板见 [04 § MR 模板](./04-代码评审流程与机制.md#mr-模板)。

### 12.4 合并策略

- 默认 **Squash merge**（feature → main）：一个 MR 一个 commit，main 历史干净。
- 重大重构用 **Merge commit**，保留分支历史。
- 禁止 force-push 已 push 的分支。

## 13. 文档规范

### 13.1 README

每个子项目（`backend/`、`ai/`、`frontend/`）必须有 `README.md`，覆盖：
1. 是什么 / 解决什么问题（一句话）
2. 快速启动（5 分钟跑起来）
3. 架构图（可选）
4. 关键目录说明
5. 常见开发任务（"加一个新 endpoint" / "加一个新指标"）
6. 故障排查（FAQ）

### 13.2 ADR

架构决策用 ADR（Architecture Decision Record）记录在 `docs/adr/0001-xxx.md`：
- **Context**：决策背景
- **Decision**：决定做什么
- **Consequences**：权衡 / 副作用
- **Alternatives considered**：考虑过的其他方案

例：
```markdown
# ADR-0001: AI 引擎选 FastAPI + 双 LLM provider

## Context
平台未来需要同时支持国内（通义千问）和国外（OpenAI 兼容）部署，
需要让上层业务代码无感切换。

## Decision
- LLM 客户端抽象为 ai.core.llm_client.LLMClient
- 从环境变量 INSTINSIGHT_LLM_PROVIDER 决定 provider
- 无 key 时 LLMClient.from_env() 抛 RuntimeError，引擎自动降级到规则兜底

## Consequences
+ 一份业务代码两套部署
+ 任何 provider 不可用都不阻塞业务
- 需要维护双份 SDK 依赖
- 缺乏统一监控（各 provider 错误码不同）

## Alternatives
- LangChain：太重，且抽象层会影响 prompt 自由度
- 只用 OpenAI SDK 兼容 dashscope：丢失 dashscope 专属功能
```

### 13.3 代码注释

- **为什么** > **是什么**。代码本身能说明"是什么"，注释说明"为什么这么写"。
- TODO 注释：`// TODO(author): 描述`，并在 issue 里建 ticket 跟踪。
- 不要写"显而易见"的注释（`i++ // 自增`）。

.PHONY: dev dev-backend dev-ai dev-frontend test lint build deploy

	cd frontend && npm run dev

	cd backend && go test ./...
	cd ai && pytest
	cd frontend && npm run test

	cd backend && golangci-lint run ./...
	cd ai && ruff check . && black --check .
	cd frontend && npm run lint

	cd backend && go build -o bin/api ./...
