## 1. P0 — 严重（24h 内修）

### P0-1 CORS 反射任意 Origin（安全）

**位置**：`backend/internal/middleware/middleware.go:14-18`
```go
origin := c.GetHeader("Origin")
if origin == "" {
    origin = "*"
}
c.Header("Access-Control-Allow-Origin", origin)
```
**问题**：`Access-Control-Allow-Origin` 直接回显请求的 `Origin`，等同于**任意站点**都可跨域读取本 API。再加上没有 `Access-Control-Allow-Credentials` 限制、没有 Auth，攻击者站点可以诱导用户浏览器调用本服务拿数据（虽然现在没数据，但生产接入 OLAP 后就是直接泄露）。

**修复**：
```go
// middleware.go —— 改为白名单
var allowedOrigins = map[string]bool{
    "http://localhost:5173": true,
    "https://insight.insta360.com": true,
}

func CORS() gin.HandlerFunc {
    return func(c *gin.Context) {
        origin := c.GetHeader("Origin")
        if allowedOrigins[origin] {
            c.Header("Access-Control-Allow-Origin", origin)
            c.Header("Vary", "Origin")
        }
        c.Header("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
        c.Header("Access-Control-Allow-Headers", "Content-Type, Authorization")
        if c.Request.Method == "OPTIONS" {
            c.AbortWithStatus(204)
            return
        }
        c.Next()
    }
}
```
> 配套：把白名单改成从 `os.Getenv("CORS_ALLOWED_ORIGINS")` 读（逗号分隔），避免硬编码。

### P0-2 LLM 输出解析容错不够（AI 正确性）

**位置**：`ai/core/prompt_builder.py:72-83`
```python
text = raw.strip()
if text.startswith("```"):
    text = text.strip("`")
    if text.startswith("json"):
        text = text[4:]
data = json.loads(text)
```
**问题**：
1. `text.strip("`")` 会去掉字符串里**所有**反引号，包括 JSON 内容里合法出现的字符（比如某些 unicode 引号附近的）；正常情况 JSON 里没反引号所以没事，但模型偶尔会塞 `` ` `` 就会破坏。
2. 只识别小写 `json` fence，不识别 ````JSON````、```` Json ````。
3. `json.loads` 失败直接抛 `ValueError`，被 `insight_engine` 的 `except Exception` 静默吞掉，日志里看不到原始 raw，无法定位是 prompt 问题还是模型问题。

**修复**：
```python
# prompt_builder.py
import json
import re
from typing import List

_FENCE_RE = re.compile(r"^```(?:json)?\s*|```\s*$", re.IGNORECASE | re.MULTILINE)

def parse_response(raw: str) -> List[Insight]:
    """解析 LLM 输出。失败时抛 ValueError, 由调用方决定兜底。"""
    text = raw.strip()
    # 仅当整个文本以 fence 包裹时才剥离, 不做全局 strip('`')
    if text.startswith("```"):
        # 用正则去掉首尾的 fence
        text = _FENCE_RE.sub("", text).strip()
    try:
        data = json.loads(text)
    except json.JSONDecodeError as e:
        # 把原始内容截断后附在异常里, 便于排障
        raise ValueError(f"LLM 输出不是合法 JSON: {e}; raw(head)={raw[:200]!r}") from e
    if not isinstance(data, list):
        raise ValueError(f"LLM 输出不是 JSON 数组, got {type(data).__name__}")
    return [Insight(**item) for item in data]
```
> 配套：在 `insight_engine._generate_with_llm` 的 except 里把 `raw[:500]` 也写进日志，否则排障很痛苦。

### P1-2 `middleware.go` 自己手写 `itoa`（反模式）

**位置**：`backend/internal/middleware/middleware.go:59-80`
```go
// itoa 避免引入 strconv(gin 已传递依赖,这里手写避免编译顺序耦合)
func itoa(n int) string {
    // ... 20 行手写整数转字符串

**问题**：注释的"避免编译顺序耦合"是**伪命题**——`strconv` 是 Go 标准库，不存在依赖问题。手写 `itoa` 既无必要又：

import "strconv"

func httpStatus(code int) string {
    switch {
    case code >= 500: return "[5xx " + strconv.Itoa(code) + "]"
    case code >= 400: return "[4xx " + strconv.Itoa(code) + "]"
    case code >= 300: return "[3xx " + strconv.Itoa(code) + "]"
    }
    return "[2xx " + strconv.Itoa(code) + "]"
}
```

### P1-3 LLM 客户端全局副作用（并发隐患）

**位置**：`ai/core/llm_client.py:83`
```python
def _call_qwen(self, messages: List[dict], timeout: float) -> str:
    import dashscope
    from dashscope import Generation
    dashscope.api_key = self.cfg.api_key  # ← 全局副作用
    resp = Generation.call(...)
```
**问题**：`dashscope.api_key` 是**模块级全局变量**。如果未来同时跑多个 provider，或在并发请求里切换 key，会互相污染。

**修复**：
```python
def _call_qwen(self, messages: List[dict], timeout: float) -> str:
    import dashscope
    from dashscope import Generation
    # 用 with 上下文设置, dashscope>=1.20 支持 DashScopeApiKey context
    try:
        from dashscope import DashScopeApiKey  # type: ignore
        with DashScopeApiKey(self.cfg.api_key):
            resp = Generation.call(model=self.cfg.model, messages=messages, result_format="message", timeout=timeout)
    except ImportError:
        # 旧版本没 context manager, 临时设全局, 用完恢复
        old = getattr(dashscope, "api_key", None)
        dashscope.api_key = self.cfg.api_key
        try:
            resp = Generation.call(model=self.cfg.model, messages=messages, result_format="message", timeout=timeout)
        finally:
            dashscope.api_key = old
    ...
```
> 或更稳妥：换用官方推荐的 `from dashscope import Generation; Generation.call(api_key=self.cfg.api_key, ...)`（per-call key），避开全局。

### P1-4 前端 ECharts 全量引入（性能）

**位置**：所有 chart 组件，如 `frontend/src/components/TrendChart.vue`、`PlatformDonut.vue`、`AgeDonut.vue`、`TrackBarChart.vue`、`RadarChart.vue`

// 然后照常 echarts.init(...) 使用
```
**预期收益**：主 chunk 从 2.1MB → ~1.2MB（gzip 715KB → ~400KB）。

### P1-5 后端无结构化日志

**位置**：`backend/internal/middleware/middleware.go:30-44`
```go

### P1-6 LLM 无重试 / 熔断

**位置**：`ai/core/insight_engine.py:53-56`
```python
except Exception as e:
    print(f"[insight-engine] LLM 失败, 回退到规则方案: {e}", file=sys.stderr)
```
**问题**：LLM 限流 / 短暂 5xx → 立即走兜底，没有重试也没有熔断。同一波请求全部打挂时，规则引擎成为唯一来源，体感"AI 不稳定"。

**修复**：
```python
# ai/core/insight_engine.py
from tenacity import retry, stop_after_attempt, wait_exponential, retry_if_exception_type
from pybreaker import CircuitBreaker

_llm_breaker = CircuitBreaker(fail_max=5, reset_timeout=30)  # 30s 半开

@retry(stop=stop_after_attempt(2), wait=wait_exponential(min=1, max=4),
       retry=retry_if_exception_type((TimeoutError, ConnectionError)))
@_llm_breaker
def _chat_with_protection(self, messages):
    return self.llm.chat(messages)

def _generate_with_llm(self, features, flt, n):
    messages = self.builder.build_messages(features, flt, max_items=n)
    raw = self._chat_with_protection(messages)
    return self.builder.parse_response(raw)
```
> requirements.txt 追加：`tenacity==8.3.0`、`pybreaker==1.2.0`

### P1-7 前端 store 与后端 mock 字段漂移风险

**位置**：`frontend/src/api/fallback-data.js` ↔ `backend/internal/mock/insight_data.go`
**问题**：前端兜底数据和后端 mock 数据是**两份手抄**，字段必须保持一致。前几次工单已经反复调整过 `kpi.value` 字段。靠人肉记忆维持同步，必然漂移。

**修复**：
- 方案 A（轻量）：写一个 `scripts/check-contract.py`，从 `backend/internal/model/types.go` 的 Go struct tag 解析 JSON 字段名，再去扫 `frontend/src/api/fallback-data.js` 验证每个对象都覆盖。CI 里跑。

# scripts/check_contract.py —— 伪代码
import re, json, pathlib

go_types = pathlib.Path("backend/internal/model/types.go").read_text()

if missing:

### P1-8 后端 `bindFilter` 无输入校验

**位置**：`backend/internal/api/handler/insight.go:25-33`
```go
func bindFilter(c *gin.Context) model.Filter {
    return model.Filter{
        DateRange: c.QueryArray("date_range"),  // ← 无长度/格式校验
        ...
    }
}
```
**问题**：
- 没有 `date_range` 长度上限 → `?date_range=x&date_range=x&...` 重复 1 万次可放大 payload
- 没有日期格式校验 → mock 阶段无所谓，接 ClickHouse 后会 SQL 报错或注入风险
- `tracks / platforms / age_bands` 没白名单 → 任意字符串都进 Filter，会污染 AI prompt

**修复**：在 `internal/model/filter.go` 加 validator：
```go
type Filter struct {
    DateRange [2]string `json:"date_range" form:"date_range"`  // 强制 2 个
    Regions   []string  `json:"regions"   form:"regions"     binding:"max=10,dive,oneof=北美 欧洲 亚太 全球"`
    ...
}

func (f *Filter) Validate() error {
    if len(f.DateRange) > 0 && len(f.DateRange) != 2 {
        return errors.New("date_range 必须为 [start, end]")
    }
    for _, d := range f.DateRange {
        if _, err := time.Parse("2006-01-02", d); err != nil {
            return fmt.Errorf("date_range 格式错: %w", err)
        }
    }
    return nil
}
```
handler 里 `if err := filter.Validate(); err != nil { c.JSON(400, model.Fail(4001, err.Error())); return }`。
